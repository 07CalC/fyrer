## Why fyrer

<CardGroup cols={3}>
  <Card title="Streaming DAG" icon="bolt">
    Tasks start as soon as dependencies succeed, up to `concurrency`. No level barriers — `web:build` starts right after `ui:build`, even while `api:build` is still running.
  </Card>
  <Card title="Content-addressed cache" icon="database">
    blake3 over `id + cmd + cwd + env + inputs`. Outputs archived as `tar.zst` relative to workspace root, restored on `⚡ Cached`.
  </Card>
  <Card title="Language agnostic" icon="layer-group">
    If it runs in a shell, fyrer can orchestrate it. Mix Rust, Go, TypeScript, Python, and more in one `fyrer.yml`.
  </Card>
  <Card title="Watch mode" icon="eye">
    `watch: true` polls `inputs` every 300ms (debounced) and restarts on change. Dependents turn `↻ Stale` in the TUI.
  </Card>
  <Card title="Interactive TUI" icon="desktop">
    Per-task log panes, `r` to restart, `K` to kill, `q` to quit. Pass `-n` for plain prefixed logs in CI.
  </Card>
  <Card title="Single binary" icon="cube">
    No daemon, no runtime. Install via `install.sh`, `cargo install fyrer`, or build from source. 6 prebuilt targets.
  </Card>
</CardGroup>

## How it works in 3 steps

<Steps>
  <Step title="Add fyrer.yml">
    Put `fyrer.yml` at your repo root and list packages + tasks. Use `depends_on: [ui:build]` or bare `build` for same-package deps.

    ```bash
    fyrer list          # see every package:task
    fyrer plan build    # preview levels (display only)
    ```
  </Step>
  <Step title="Run">
    ```bash
    fyrer run build -n   # CI: plain logs, exit code signals failure
    fyrer run dev        # TUI: all dev servers, streaming logs
    ```

    Streaming order: `api:build` and `ui:build` start together; `web:build` starts as soon as `ui:build` succeeds.
  </Step>
  <Step title="Iterate">
    Edit code, save, and watch-mode tasks restart automatically. Unchanged `build` tasks hit `⚡ Cached` and restore outputs instantly.

    ```bash
    fyrer run build   # only changed packages rebuild
    ```
  </Step>
</Steps>

    ### Configuration you can trust

    ```yaml
    tasks:
      build:
        cmd: bun build src --outdir dist
        inputs: [src/**, package.json]
        outputs: [dist/**]
        ignore: [node_modules/**]
        cache: true
        timeout: 5m
        cwd: subdir
        env: { NODE_ENV: production }
        env_file: .env.production
    ```

    Validated at startup: unique names, relative `root`/`cwd`/`env_file` that exist, valid `inputs`/`outputs` globs, `cache` ≠ `persistent`/`watch`.
