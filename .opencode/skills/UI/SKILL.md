Design a premium developer-tool landing page with a highly polished, technical aesthetic.

Overall:
- Dark-first interface with an almost-black background (#08090a).
- Use subtle off-white text, muted gray secondary text, and one distinctive accent color.
- Typography should feel developer-oriented: Geist, Inter, or a similar modern sans-serif.
- Use monospace typography selectively for commands, package names, metrics, code, and technical labels.
- Avoid excessive gradients, glassmorphism, huge rounded cards, or generic SaaS visuals.
- Make the product feel like serious infrastructure used by professional developers.

Hero:
- Small eyebrow badge such as "Open source • Built for developers".
- Strong headline, 2–3 lines maximum.
- Headline should communicate the core value immediately.
- Supporting copy should be concise and technical rather than marketing-heavy.
- Primary CTA: "Get Started".
- Secondary CTA: "View on GitHub".
- Show a realistic terminal/code panel beneath or beside the hero.
- Terminal should contain believable commands and output rather than placeholder lorem ipsum.
- Add subtle animated cursor, command execution, or output transitions.

Navigation:
- Minimal sticky navbar.
- Logo on the left.
- Links: Docs, GitHub, Changelog, Blog.
- CTA on the right.
- Navbar should become slightly opaque/backdrop-blurred when scrolling.
- Keep navigation compact and unobtrusive.

Product visualization:
- Prefer actual product UI, terminal output, code snippets, graphs, logs, dependency trees, or architecture diagrams over stock imagery.
- Use large technical screenshots with subtle borders and shadows.
- Screenshots should feel like real developer tooling rather than fake dashboard cards.

Sections:
1. Hero
2. Product/demo visualization
3. "Built for your workflow" feature grid
4. Technical architecture / how it works
5. Performance metrics
6. Code/API example
7. Comparison or migration section
8. Open-source/community section
9. Final CTA
10. Minimal footer

Feature cards:
- Use 3–4 columns on desktop.
- Keep cards compact.
- Each card should contain:
  - small icon
  - short technical title
  - 1–2 sentence description
  - optional code/metric/detail
- Avoid generic feature copy like "Powerful and easy to use."

Visual language:
- 1px borders with very low contrast.
- Subtle radial gradients only where they add depth.
- Fine grid/noise textures can be used in the hero background.
- Use generous whitespace.
- 12–16px corner radius for major containers.
- Avoid excessive rounded-pill UI.
- Use tiny status indicators, command prompts, version numbers, and technical metadata as visual details.
- Add subtle horizontal separators between major sections.

Code blocks:
- Dark code panels with syntax highlighting.
- Include a copy button.
- Use realistic commands:
  `$ tool init`
  `$ tool build`
  `$ tool deploy`
- Show realistic output:
  `✓ 42 packages resolved`
  `✓ cache hit`
  `✓ build completed in 1.82s`

Motion:
- Animations should be subtle and purposeful.
- Use fade/slide-in on scroll.
- Slight terminal typing animation.
- Hover states should use small translation/glow/border changes.
- Never make the site feel like a flashy AI landing page.

Responsive:
- Mobile-first.
- Hero typography scales smoothly.
- Navigation collapses cleanly.
- Code blocks remain horizontally scrollable.
- Feature grid becomes one column.
- Avoid horizontal overflow.

Important:
- The website should immediately communicate "this is a serious developer tool."
- Prioritize credibility and technical detail over marketing decoration.
- Every visual element should support the product.
- Make the design feel closer to a high-quality open-source infrastructure project than a generic SaaS startup.
